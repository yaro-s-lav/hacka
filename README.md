# АРМ-112 — учебный тренажёр

Тренажёр для студентов и преподавателей: генерация согласованных сценариев по 1 283 типам ЕКП, карточки 112, работа ДДС, практические занятия, SIP-звонки с русской озвучкой, оценка, отчёты и аудит. Пропущенные карточки сохраняют поля и время обработки; повторный выбор продолжает ту же попытку без учёта паузы.

## Требования

Установите Git, Docker Engine и Docker Compose v2. Проверка: `git --version`, `docker --version`, `docker compose version`. При первой сборке нужен интернет для Docker-образов, Python-пакетов и голосовых/нейросетевых моделей. Голосовые модели и LanguageTool загружаются при сборке, поэтому первый полный запуск занимает больше времени, чем обновление приложения.

## Получить и запустить

```bash
git clone https://github.com/yaro-s-lav/hacka.git
cd hacka
# .env уже включён с демонстрационными настройками.
# Если файла нет: cp .env.example .env
docker compose up -d --build
docker compose ps
curl http://localhost:8000/health
```

Откройте `http://localhost:8000` либо `http://IP_СЕРВЕРА:8000`. В исходном окружении доступны:

| Роль | Логин | Пароль |
| --- | --- | --- |
| Студент | student | student12345 |
| Преподаватель | teacher | teacher12345 |
| Администратор | admin | admin12345 |

Студент видит только назначенные преподавателем задания; без назначения список пуст. Для демонстрации войдите как `teacher`, откройте «Занятия», выберите задания и `student`, нажмите «Назначить занятие», затем «Начать занятие». Заготовки можно заранее сохранить без студентов и выдавать повторно. Все исходные 96 задач PDF доступны преподавателю в «Билетах и задачах».

Обычный запуск включает приложение, PostgreSQL, Redis и резервное копирование. Для звонков и нейросетевой оценки используйте полный запуск ниже. Генерация сценариев ЕКП работает без Ollama.

### Выбор движка русской озвучки

По умолчанию используется лёгкий CPU-движок Piper:

```dotenv
VOICE_ENGINE=piper
```

Для сравнения доступен Silero `v5_5_ru` с автоматическими ударениями и несколькими русскими голосами. Переключение обратимо:

```dotenv
VOICE_ENGINE=silero
```

После изменения запустите оба профиля, чтобы поднять Silero-сервис:

```bash
docker compose --profile voip --profile silero up -d --build app voice-silero
```

Для возврата к Piper верните `VOICE_ENGINE=piper` и выполните:

```bash
docker compose --profile voip up -d --build app voice
```

Silero требует больше места и оперативной памяти, чем Piper; его модель загружается в отдельный контейнер и не изменяет SIP/API-контракт.

## Запуск со звонками и оценкой

```bash
docker compose --profile voip --profile ai up -d --build
docker compose --profile voip --profile ai ps
```

Для локального запуска, включая звонки, откройте **`http://localhost:8000`**, разрешите микрофон и нажмите «Подключить телефон», затем выберите сценарий и «Учебный звонок». Браузер разрешает микрофон на `localhost` по HTTP; SIP подключается к локальному Asterisk на порту 8088. На своём компьютере HTTPS и установка сертификата не требуются. HTTPS на 8443 нужен при доступе с другого компьютера по IP или DNS-имени.

При работе с другого компьютера задайте в `.env`:

```dotenv
ARM_HOST=192.168.1.100
SIP_PUBLIC_ADDRESS=192.168.1.100
```

Замените адрес на доступный студентам IP сервера. `ARM_HOST` также может быть DNS-именем; порт и протокол в него не включаются. Перезапустите:

```bash
docker compose --profile voip up -d --force-recreate app asterisk turn gateway
```

Адрес интерфейса: `https://192.168.1.100:8443`. Caddy использует локальный центр сертификации. Установите его корневой сертификат в доверенные на компьютере студента, иначе браузер может блокировать SIP/WebSocket:

```bash
docker compose cp gateway:/data/caddy/pki/authorities/local/root.crt ./arm112-root.crt
```

Для связи между компьютерами откройте на сервере TCP 8443, TCP/UDP 3478 и UDP 10000–10100. Приложение по TCP 8000 нужно только при прямом HTTP-доступе; интерфейс Asterisk TCP 8088 доступен также через HTTPS-шлюз.

## Окружение

В репозитории есть `.env` для демонстрации и `.env.example` как полный шаблон. Они содержат учебные значения, а не секреты действующего защищённого контура. Перед доступом из сети замените `POSTGRES_PASSWORD`, `SECRET_KEY`, `ADMIN_PASSWORD`, `TEACHER_PASSWORD`, `STUDENT_PASSWORD`, `ASTERISK_AMI_SECRET` и `TURN_SECRET`. Не коммитьте действующие пароли. `BACKUP_DIR` задаёт каталог полных резервных копий; по умолчанию это `./backups`.

Для генерации отдельного секрета:

```bash
openssl rand -hex 32
```

Используйте разные значения для каждого секрета. Пароль PostgreSQL должен подходить для URL подключения; шестнадцатеричная строка подходит. На уже запущенной базе изменение `POSTGRES_PASSWORD` в `.env` не меняет пароль пользователя PostgreSQL; изменения паролей исходных аккаунтов также не заменяют существующие учётные записи. На новом сервере задайте значения **до первого запуска**; существующих пользователей меняйте через кабинет администратора.

## Обновление

```bash
# Сначала сохраните копию базы.
docker compose exec -T backup sh /backup.sh
# Если вы редактировали включённый в Git .env, сохраните свои настройки вне проекта.
cp .env ../arm112-env.saved
git pull --ff-only
docker compose --profile voip --profile ai up -d --build
docker compose ps
curl http://localhost:8000/health
```

Если Git сообщает о конфликте локально изменённого `.env`, сначала сохраните его, восстановите только этот файл из Git командой `git restore .env`, выполните `git pull --ff-only`, затем верните нужные настройки из сохранённой копии **до пересоздания контейнеров**. Используйте те же профили, что при первоначальном запуске. После обновления интерфейса нажмите Ctrl+F5.

## Управление и диагностика

```bash
docker compose logs --tail=100 app
docker compose --profile voip logs --tail=100 voice asterisk gateway
docker compose --profile ai logs --tail=100 ml grammar
# Остановить контейнеры, сохранив данные:
docker compose --profile voip --profile ai down
# Запустить снова:
docker compose --profile voip --profile ai up -d
```

Данные базы, аудио и настройки SIP хранятся в Docker-томах. `docker compose down -v` удаляет тома и данные; для обычной остановки его не используйте.

## Карточки и перенос данных

При первом запуске импортируются классификатор ЕКП и 96 задач из исходных материалов, создаются демонстрационные пользователи, 4 исходных сценария и **32 постоянные карточки практики**: 24 базовые и 8 для новых рабочих процессов. Каталоги карточек включены в `data/scenarios/practice.json` и `data/scenarios/workflows.json`: реплики, эталоны, службы и сложность сохраняются. Карточки автоматически устанавливаются на новой и существующей базе, повторный запуск не создаёт дубликатов и не перезаписывает правки преподавателя. Привязки ЕКП восстанавливаются по кодам, а не по идентификаторам старой базы. Сценарии, созданные преподавателем, назначенные занятия, попытки студентов и дополнительные пользовательские сценарии работающего сервера хранятся в PostgreSQL. Постоянные 32 карточки уже входят в приложение и не требуют переноса базы. Историю попыток и пользовательские данные `git clone` или `git pull` не переносит. Для переноса текущего состояния используйте полную резервную копию: она включает базу, аудио и вложения. Копии создаются каждые 23 часа; ручной запуск доступен администратору в «Мониторинге». В «Мониторинге» доступны «Скачать всё» и загрузка одного `.tar.gz` на другом сервере: восстанавливаются пользователи, карточки, занятия, история, аудио и вложения. Версии приложения должны совпадать. Отдельные кнопки «Скачать БД» / «Восстановить БД» работают только с PostgreSQL. Настройки `.env` нового сервера задаются отдельно; после переноса войдите заново и переподключите SIP-телефоны. Проверка резервной копии без замены рабочей базы: `make verify-backup`. Подробности эксплуатации: [docs/OPERATIONS.md](docs/OPERATIONS.md).

Преподаватель создаёт и утверждает сценарии, назначает практические занятия студентам и следит за карточками в мониторинге. Студент может также выбирать утверждённые карточки для свободной тренировки.

### Новые опросные карты, SMS и аппаратный SIP

[Порядок демонстрации, постоянные карточки, подключение РТУ Т16Р и границы интеграций](docs/HACKATHON_DEMO.md).

При сохранении карточки 112 время создания фиксируется; дальнейшая отработка учитывается отдельно. Есть структурированные опросные карты, дополнения с блокировкой редактирования, количество пострадавших, оформление вызова без контакта, связи повторных обращений, напоминания, помощь старшего специалиста и учебная переписка SMS. Эталон ответов преподаватель задаёт в редакторе; ответы проверяются в отчёте.

Выбор активного XLSX закреплён через `CLASSIFIER_FILE` (по умолчанию `046_24`). Поддерживаются обе предоставленные структуры — 99 и 90 колонок — с различным сопоставлением служебных блоков. Добавление другого файла в `source_materials` не меняет активный классификатор.
